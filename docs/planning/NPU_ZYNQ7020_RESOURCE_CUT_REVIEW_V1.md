# XC7Z020 资源裁剪审查 V1

状态：`REVIEW_REQUIRED / 不执行 RTL 删除`

日期：2026-09-07

## 1. 审查边界

本审查基于当前已签核的 RTL、Vivado 2024.1 OOC 报告和已批准的 A1-A7。目标是找出“有风险但确实可以做成产品配置”的裁剪点，不把理论位数或综合猜测写成实测结果。

当前物理基线：

| 层级 | 器件/工具 | LUT | FF | BRAM | DSP | 时序 |
|---|---|---:|---:|---:|---:|---|
| 单时钟传统 NPU | XC7Z020，Vivado 2024.1 | 2126 | 1916 | 0 | 4 | WNS `+0.060 ns`，WHS `+0.040 ns` |
| 4->2->2 Tile | 已有 OOC 参考 | 3152 | 1972 | 0 | 0 | WNS `+0.213 ns`，WHS `+0.026 ns` |
| Host Bridge 系统 | 已有 OOC 参考 | 3682 | 2486 | 4 RAMB36 | 0 | Host/Tile 均通过 |

单时钟 NPU 的 2126 LUT 中有 1014 个被报告为 LUTRAM；当前模型数组为 `634 x 32 bit`，mask staging/active 为两组 `19 x 32 bit`。这说明模型配置存储是当前最值得先审计的面积来源，但不能直接把 1014 LUT 全部归因给某一个数组，最终数字必须由 A/B OOC 证明。

## 2. 裁剪分类

### 2.0 先不实例化历史 Pulse Host Bridge

- **对象**：最终“传统 NPU + ENeuron”生产顶层不实例化历史 `digital_snn_host_bridge_system`（4->2->2 Pulse Tile）。源码和回归继续保留，但不进入 NPU bitstream。
- **依据**：已有层次报告中该历史系统约为 `3682 LUT / 2486 FF / 4 RAMB36`，其中 Tile 约 `3078 LUT / 1970 FF`、controller `506 LUT / 361 FF`、bridge `109 LUT / 155 FF`。该报告来自 `xc7a35tcpg236-1`，只能作为结构参考，不能替代 XC7Z020 物理证据。
- **实际效果**：这是架构边界选择，不是对当前 NPU OOC 的 RTL 优化；如果生产顶层本来就不实例化它，则可避免整块历史系统的面积和 BRAM 代价。
- **风险**：失去 Pulse Tile 的片上训练路径；不能再把该路径和传统 NPU 共用一个 bitstream。
- **推荐等级**：**立即执行于顶层规划**，但不修改历史模块。

### 2.1 可立即做成产品配置

这些项目不改变默认训练基线，只新增综合参数或独立顶层；适合先做 A/B 实测。

#### C1：固定模型部署，删除 staging/upload 路径

- **裁剪对象**：`model_staging`、模型逐字写入状态机、模型提交/回滚检查；把已训练模型作为只读 ROM/BRAM 初始化，保留 `model_valid` 的静态启动检查。
- **依据**：当前 `model_staging` 为约 20.3 Kbit，mask staging/active 另有约 1.2 Kbit；单时钟 OOC 已出现 1014 LUTRAM。
- **预期收益**：预计主要节省 LUT/LUTRAM，量级约 `500~1000 LUT`；若改为一块 RAMB36，可能增加 `1 RAMB36`，但具体收益必须以 Vivado 实测确认。该范围是工程估算，不是测量值。
- **功能损失**：不能在运行期上传新模型，不能原子替换模型，掉电后模型更新依赖重新生成 bitstream/初始化文件。
- **故障模式**：初始化文件与模型版本不一致时，可能得到“可运行但模型错误”的结果；需要保留模型哈希或版本常量检查。
- **合同影响**：破坏当前在线模型配置合同；不影响 A1-A7 的命令字段，但必须作为新的 `INFER_FIXED_MODEL` 配置重新审批。
- **推荐等级**：**高**，是当前最值得验证的裁剪。
- **验证**：保持同一模型和 20×100 随机样本，比较逐拍 logits、mask_epoch、结果 beat；重新跑 XC7Z020 综合、布局布线、资源和时序。

#### C2：推理专用 ENeuron，删除学习状态和提交通路

- **裁剪对象**：在 `digital_lif_engine`/Tile 的 `INFER_ONLY` 参数下删除 eligibility、pre/post trace、snapshot、modulator、weight write 和相关状态机；权重改为只读初始化。
- **预期收益**：每条突触可删除多组工作寄存器和学习控制逻辑。当前单核为 `813 LUT / 544 FF`，Tile 为 `3152 LUT / 1972 FF`；预计 Tile 可节省约 `15%~35% LUT`、`20%~40% FF`，必须以综合结果校正。
- **功能损失**：该 bitstream 不能自训练、不能局部剪枝提交、不能在线改权重；只能用于冻结模型推理。
- **故障模式**：误把训练命令送入推理 bitstream 时，若没有明确错误响应会造成 Host 死锁或静默忽略；必须保留 fail-closed 错误响应。
- **合同影响**：不应替换当前 M1-M4 训练基线，只能作为独立产品配置；A1-A7 顶层协议仍可保留，但训练 opcode 必须明确拒绝。
- **推荐等级**：**高**，适合和 C1 组合成为“最小推理版”。
- **验证**：训练版与推理版使用同一冻结权重，逐 beat 比较输出；对所有训练/提交命令做负向测试；再跑 OOC。

#### C3：固定拓扑特化

- **裁剪对象**：对已经固定的 `64->32->10` 或 `4->2->2` 版本，删除通用层数、地址范围和可变扇入的多路选择；保留端口协议不变。
- **预期收益**：预计节省约 `50~150 LUT`、`20~60 FF`，收益取决于综合器是否已经常量传播；不能保证一定下降。
- **功能损失**：不能用同一 bitstream 改变层宽、神经元数量或地址布局。
- **故障模式**：Host 仍按通用地址发送时可能访问错误对象；必须在 wrapper 返回确定的 `BAD_FIELD/BAD_STATE`。
- **合同影响**：协议字段含义不变，但实现参数冻结，需要新增构建配置记录。
- **推荐等级**：**中高**。
- **验证**：固定拓扑 golden vector、非法地址、边界地址、完整随机回归和 OOC 前后差分。

#### C4：部署版缩短 ID/epoch 宽度

- **裁剪对象**：将固定板级任务中的 `sample_id`、`mask_epoch`、`commit_id` 从 32/16 bit 缩短为经审计的 16/8 bit；FIFO payload 和响应字段同步改变。
- **预期收益**：减少 sideband 寄存器、比较器和 FIFO 数据位；通常是几十个 FF/LUT，若 FIFO 物理宽度跨过原语边界才会减少 BRAM，否则 BRAM 可能不变。
- **功能损失**：ID 回绕更快，长时间运行或多任务并发的关联空间变小。
- **故障模式**：回绕后旧结果与新样本混淆；必须保留窗口内唯一性检查。
- **合同影响**：直接改变 A1/A3/A6 字段宽度，必须新建协议版本，不能悄悄替换 V1。
- **推荐等级**：**中**，仅在 C1/C2 后仍受资源约束时采用。

#### C5：生产版关闭调试导出

- **裁剪对象**：`debug_host_rst`、`debug_tile_rst`、`debug_fifo_rst_busy`、`debug_tile_ready/busy/protocol_error/output_spikes` 等顶层观测端口。
- **预期收益**：当前这些信号多为已有状态的直接连线，综合器可能已经优化，预计收益为 `0~30 LUT/FF`，不能高估。
- **功能损失**：板上故障定位和在线状态观测变差。
- **合同影响**：不影响计算协议；建议只通过 `DEBUG=0` 构建参数关闭。
- **推荐等级**：**中低**，收益小但风险也小。

#### C5a：局部剪枝 telemetry 关闭

- **裁剪对象**：`local_prune_gate_2of4.sv` 中的生产遥测计数器，例如 12 个 32-bit 计数器（提交数、非法数、hidden/output dense、issued、ops、saved、inactive、groups 等）。
- **依据**：当前 gate OOC 为 `200 LUT / 499 FF`；这些计数器合计约 `384 FF`，并带有递增加法逻辑。
- **预期收益**：预计可删除大部分约 `384 FF` 及其更新逻辑；精确 LUT/FF 差值必须由 Vivado A/B 实测。
- **功能损失**：生产运行时看不到详细剪枝统计；保留 2:4 mask、utility、ID、exactly-once 和错误语义。
- **合同影响**：不改变剪枝决策，只改变观测面；建议 `ENABLE_TELEMETRY=0`，仿真/签核默认值保持 1。
- **推荐等级**：**高**，适合在确认生产不需要统计后实施。

### 2.2 有真实收益但风险较高

#### C6：单槽 snapshot 改为无 snapshot 的即时提交

- **裁剪对象**：删除 `eligibility_snapshot`/`eligibility_snapshot_work`，在训练段结束时直接使用当前 eligibility。
- **潜在收益**：每个突触删除两份快照存储和扫描状态；对小 Tile 可能只节省几十到几百 FF/LUT，对大阵列则线性增长。
- **功能损失**：不能把资格迹线冻结后等待延迟调制；下一 episode 的状态可能污染本次反馈。
- **故障模式**：延迟反馈、重复反馈和 Host 背压下出现错误权重更新。
- **合同影响**：直接破坏 M1-M4 的延迟学习和 exactly-once 证据，当前不应采用。
- **推荐等级**：**不建议**；只有在完全同步反馈、无跨 episode 延迟的专用模式下重新设计。

#### C7：删除 `weights_work`/`pre_trace_work`/`eligibility_work`，改为原地更新

- **潜在收益**：减少工作寄存器阵列。
- **功能损失**：破坏 TICK 的事务原子性，输入扫描顺序会影响结果，异常中止时无法保持旧状态。
- **合同影响**：违反现有 ready/done、状态原子提交和逐周期参考模型合同。
- **推荐等级**：**禁止作为普通裁剪**。只有重写成 RAM+事务缓冲的新架构时才可讨论。

#### C8：减少异步 FIFO 深度或合并样本/结果通道

- **潜在收益**：可能减少 FIFO 控制逻辑；但 128-bit 宽度下深度减小未必减少 RAMB36 数量。
- **功能损失**：背压裕量下降；合并通道会重新引入跨流排序和 framing 状态。
- **合同影响**：A5 已冻结四条 FIFO 的宽度、深度、FWFT 和 CDC 参数，不能直接修改。
- **推荐等级**：**暂不采用**；必须新建 P15-T1.x 协议裁定并重新做双时钟协同仿真。

#### C9：缩小膜电位、eligibility、trace 和权重位宽

- **潜在收益**：大阵列中可线性节省寄存器/RAM 位数及加法器宽度。
- **功能损失**：饱和边界、学习收敛和分类精度改变；小网络的当前 golden vector 不再适用。
- **合同影响**：改变定点数据通路，不属于无语义裁剪。
- **推荐等级**：**中风险研究项**；必须先做 Python 量化敏感性扫描，再做 RTL/OOC。

### 2.3 不应裁剪

以下项目虽然可能带来少量面积收益，但会直接破坏已经签核的正确性或物理安全边界：

- 四个强制 DSP48E1；TR11 要求保留 DSP，不能改成 LUT 乘法器。
- CDC 同步器、FIFO reset-busy、ready/valid payload 稳定保持。
- A3 fence、单样本 8 beat/结果 10 beat 计数、`sample_id/mask_epoch` 原子 sideband。
- `snapshot_valid`、`commit_id` 单调/重复保护、INFER 权重写保护。
- Tile 的 all-done barrier 和一拍隐藏层 pending 路由。
- 饱和而非回绕的权重、膜电位、trace、eligibility 算术。
- `protocol_error` 首错/冻结语义和 Host 可见错误响应。
- 仅位于 `ifndef SYNTHESIS` 的形式断言和仿真检查；它们不进入综合网表，删除它们基本不省硬件。

## 3. 推荐实施顺序

1. 生产顶层排除历史 Pulse Host Bridge，不改其源码和回归。
2. 先做 C1：固定模型 ROM/BRAM 配置，与当前可训练版逐拍等价。
3. 再做 C2：独立 `INFER_ONLY` ENeuron bitstream，不改变训练基线。
4. 在剪枝部署中做 C5a telemetry off，再做 C5 debug outputs off。
5. 若仍需压缩，再做 C3 固定拓扑特化。
6. C4 以及 C6-C9 必须先形成新的协议/算法裁定，不能直接改当前签核 RTL。

## 4. 统一验收门

任何裁剪候选都必须同时满足：

- Python/RTL golden vector 逐拍一致，或明确记录为新模型/新协议；
- 原有负向、背压、reset、INFER 冻结和重复提交测试没有回归；
- Vivado 2024.1、`xc7z020clg400-1` 重新完成 utilization、timing、route、DRC；
- 报告同时给出裁剪前后 LUT、FF、BRAM、DSP、WNS/WHS 和功耗估算；
- 收益写成实测差值，不用“位数除以 LUT”替代综合结果；
- 新配置有独立名称、参数清单和回滚路径，不覆盖当前 M1-M4 训练基线。

## 5. 结论

当前最有价值的资源路线不是删除神经元核心行为，而是把“训练期硬件”和“冻结推理期硬件”拆成两个构建配置：训练版保留 M1-M4 的完整证据，推理版删除在线模型上传、eligibility、snapshot 和调制提交，并把模型放入初始化 ROM/BRAM。这样风险可隔离、收益可实测，也不会误伤已经批准的 A1-A7、CDC、原子性和四 DSP 合同。
