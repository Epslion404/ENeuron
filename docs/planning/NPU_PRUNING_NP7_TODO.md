## 1. 目标

NP7 要证明结构掩码和输入活动在权重读取、计算发射之前生效，使 `2:4` 稀疏不只减少逻辑计数，还能减少实际存储请求和共享 lane 周期。

当前活动边界：NP7.0-NP7.6 的软件、RTL、形式和负向证据继续作为活动功能门；NP7.7 的旧 `xc7z020clg400-1` 物理结果只作历史参考。若要关闭目标器件物理门，必须在 `xc7z020clg484-2` 上重新绑定 RTL、Vivado、报告和摘要。

完成后允许声明的上限是“XC7Z020 上可综合的共享突触执行原型，在冻结任务中实现了可复现的读取、操作和周期减少”。它仍不等于第三方 DPU 插件、板级吞吐提升、真实功耗下降或通用 NPU。

## 2. KISS 架构

首版只实现一个共享突触执行单元，不复制完整神经元核心：

```text
组描述符 + 输入活动
        |
        v
结构掩码 AND 活动掩码
        |
        v
请求生成器 -> 同步权重 RAM -> 1/2/4/8 条共享 lane
        |                              |
        +---------- 周期账本 <---------+
                                       |
                                       v
                              饱和突触和 + done
```

- 稠密格式保存四个权重；稀疏格式保存两个权重和两个 2-bit 位置索引。结构掩码由位置索引重建，不同时保存第二份可漂移真值。
- V1 每个逻辑组固定四输入、保留两条连接；不支持任意稀疏率和可变长度链表。
- `issue_mask=0` 走零突触快速路径，不发 RAM 请求和 lane 操作，但仍由上层在同一逻辑 tick 推进泄放、阈值和时间状态。
- 权重读取、lane 发射和完成响应使用 ready/valid；单个组在完成前不接受第二个执行请求。
- 首版只读执行 RAM。训练权重和剪枝提交通过 CONFIG 装载口预先写入，运行中不实现缓存一致性或双写镜像。

## 3. 两种存储格式

### 3.1 稠密基线

每组一个固定宽度记录：四个有符号权重。请求生成器按 lane 数发出四条候选操作，再由输入活动决定是否真正执行；结构侧不跳过。

### 3.2 稀疏 `2:4`

每组记录两个有符号权重和两个位置索引。读取后只展开两条结构保留连接，再与输入活动相交。非法位置重复或越界必须在 CONFIG 写入时拒绝，执行路径不重复做排序。

两种格式必须具有相同的权重位宽、饱和规则、输入编码和最终突触和。格式差异只影响读取数据量、请求数和执行周期。

## 4. 周期与计数合同

每个已接受执行事务恰好产生一次 `done`。正式账本至少记录：

- `group_read_requests`：实际被 RAM 接受的组读取数；
- `weight_values_fetched`：从存储格式取出的权重槽数量；
- `lane_ops_issued`：真正进入乘加/条件加 lane 的操作数；
- `zero_fast_paths`：没有任何有效突触时直接完成的事务数；
- `busy_cycles`、`stall_cycles` 和 `completed_groups`；
- 持续输入下的 groups/cycle 与每逻辑 tick 总周期。

结构跳过、输入为零和背压等待分开计数，禁止把同一条连接重复记为多种收益。

## 6. 停止条件

- 稀疏格式需要额外读取，导致实际权重槽读取不降。
- 周期减少只来自改变神经元方程、阈值、泄放或训练协议。
- dense/sparse 最终突触和或网络状态不能 bit-exact。
- 负向实现仍能通过性能 verifier。
- 需要任意稀疏、缓存一致性、多端口写回或完整 AXI/DMA 才能继续。
- NP7.0-NP7.6 任一硬门失败；此时不得运行 NP7 Vivado。

## 7. 证据边界

- NP6 的资源报告不能替代 NP7 共享 RAM/lane 的新实现报告。
- 周期 oracle 和 RTL 计数只能证明数字执行路径，不证明以太网、DMA、PS 软件或板级端到端吞吐。
- vector-less 功耗不作为 NP7 收益门；真实功耗留给有活动文件或板测的后续阶段。
- 当前官方器件资料只用于约束同步块 RAM和时序实现方式，最终映射仍以本项目 Vivado 报告为准。
