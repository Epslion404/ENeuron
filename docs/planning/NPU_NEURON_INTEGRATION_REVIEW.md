# 传统 NPU + ENeuron 集成审核稿

状态：`REVIEW_REQUIRED`
适用基线：NP7 `NP7.0-NP7.7_SIGNED_OFF`；本稿只做静态规划，不授权新 RTL、Vivado 或板级测试。

## 1. 目标

在同一 FPGA 设计中保留传统 INT8 NPU 的确定性推理数据通路，并接入 ENeuron 神经元作为局部剪枝和动态门控控制器。神经元只决定“哪些局部连接允许进入下一次 NPU 计算”，不替代 NPU 的乘加、累加、量化和输出校验。

## 2. 已有证据与未证明事项

已具备：NP7 共享 BRAM/共享 lane 的软件、周期、形式、负向和 Vivado 物理证据；8/8 `xc7z020clg400-1`、100 MHz 配置收敛。
尚未证明：传统 NPU 与神经元在同一顶层的资源、时序、DMA/网口端到端吞吐、准确率保持、在线更新稳定性和板级功耗。

## 3. 建议的最小集成边界

1. 传统 NPU 保持原有权重、激活和结果协议，作为性能基线。
2. ENeuron 接收每个局部块的活动摘要，输出固定宽度的门控位图和有效周期。
3. 门控位图在 NPU 的权重读取请求前生效；禁止组合路径穿过 NPU 的结果输出。
4. 门控更新采用提交/生效边界：一批计算期间冻结，下一批开始时原子切换。
5. 默认提供旁路模式，使“传统 NPU”和“传统 NPU + 神经元门控”使用同一输入、权重和输出检查。

## 4. 必须先裁定的事项

| 编号 | 裁定问题 | 默认建议 |
|---|---|---|
| I1 | 门控粒度 | 先按 NPU 局部块/输出通道，不直接关闭任意单个乘加 |
| I2 | 生效时刻 | 批边界原子提交，禁止计算中途改掩码 |
| I3 | 旁路基线 | 必须保留，并与门控模式逐样本 bit-exact 对比 |
| I4 | 训练职责 | Host/PS 负责标签、奖励和参数更新；PL 只执行门控与状态采集 |
| I5 | 性能门槛 | 分别报告读取量、有效乘加、总周期、吞吐和准确率，不用单一指标替代 |
| I6 | 物理验证 | 先做独立集成 OOC，再做 Zynq-7020 顶层；每次绑定确切 Vivado 版本和 HEAD |

## 5. 进入实现前的硬门

- [ ] 管理员批准 I1-I6，并明确首个 NPU 模型、输入尺寸和 INT8 量化格式。
- [ ] Python 参考模型能在旁路/门控两种模式下逐样本复现输出与门控决策。
- [ ] 明确最坏情况：门控全开、全关、频繁切换、背压和状态清除。
- [ ] 明确资源预算：LUT、FF、BRAM、DSP、时钟和可接受 WNS。
- [ ] 形成独立集成顶层与 testbench 任务后，才允许实现 RTL。

## 6. 禁止的提前结论

在上述硬门通过前，不得宣称神经元已经提升传统 NPU 的板级吞吐、准确率、功耗或通用训练能力；NP7 的局部周期收益不能直接外推到集成系统。

## 7. 2026-09-03 静态审计结论

当前文档仍停在 `REVIEW_REQUIRED`，尚未授权集成 RTL、Vivado 或板级测试。进入实现前必须补齐以下最小材料包：

1. 冻结首个传统 NPU 模型、输入尺寸、INT8 权重/激活格式、累加位宽和量化位置。
2. 冻结活动摘要、门控位图宽度、`valid/ready`、背压、复位、跨时钟和 DMA/网口边界的逐周期协议。
3. 建立 Python 旁路/门控参考模型、固定向量和逐样本 bit-exact 验收器；旁路模式必须与传统 NPU 输出逐字段一致。
4. 固定全开、全关、频繁切换、零路径、背压、状态清除和提交边界等最坏情况矩阵，并规定每种情形的预期状态转移。
5. 给出集成级 LUT、FF、BRAM、DSP、时钟、WNS/TNS、吞吐、准确率和功耗门槛，分别报告局部执行单元与整机结果。
6. 形成独立集成顶层、testbench、资源/时序 runner 和证据摘要；任何结果必须绑定确切 Vivado 版本与 Git HEAD。
7. 将在线更新稳定性、训练/推理冻结以及 mask 提交后的生效边界写成可观察、可验证的合同。

在管理员明确批准 I1-I6 及上述材料包前，下一步仅限文档、参考模型规划和静态审计；不得创建集成业务 RTL，也不得运行新的 Vivado。
