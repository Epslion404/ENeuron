# 传统 NPU + 神经元局部剪枝与动态门控计划

状态：`DRAFT_FOR_REVIEW`

日期：2026-09-02

本文件是当前项目的新主线规划。它把已完成的神经元和局部剪枝成果，接入一个传统 INT8 NPU，目标是在 FPGA 上同时部署两者：NPU 负责数据平面，神经元负责局部活动观察、剪枝建议和动态门控。用户批准本文件前，只允许做软件模型、接口审计和文档维护，不开始新的业务 RTL。

## 1. 当前目标

构建一个可复现、可测量的 FPGA 原型：

```text
输入 / 权重
      |
      v
传统 INT8 NPU  ---- 局部统计 ----> 神经元控制器
      ^                              |
      |<---- structural_mask --------+
      |<---- activity/issue_mask ----+
      v
输出与性能账本
```

需要证明的不是“神经元看起来像生物神经元”，而是以下工程闭环：

1. 稠密 NPU 能独立完成固定任务。
2. 神经元只根据本地活动、贡献和既有训练事件生成局部候选掩码。
3. 掩码在权重读取和计算发射之前生效。
4. 稀疏版本保持任务能力，同时减少真实读取、计算发射或周期。
5. TRAIN 与 INFER 的状态边界清晰，推理期间模型不会被偷偷修改。
6. Python、RTL、形式检查和 XC7Z020 实现结果能够逐层对账。

本计划只承诺“传统 NPU 的局部结构化剪枝与动态门控原型”。它不承诺通用 NPU 优化器、全局最优剪枝、任意第三方 DPU 插件或通用 AI 自训练。

## 2. 已知基线与事实边界

- NP7 已合并，证明了共享 dense/sparse 执行单元和 `1/2/4/8 lane` 的协议、形式与实现证据。
- NP7 不是完整传统 INT8 NPU，也不能单独证明端到端推理加速。
- 局部剪枝软件阶段已证明 `2:4`、本地 utility、原子提交和 INFER 冻结的可行性；这些结果不是 RTL、功耗或板级吞吐结果。
- 已有 `4 -> 2 -> 2` 脉冲网络只作为神经元回归和控制协议基线，不作为 NPU 性能基线。
- XC7Z020 的资源和时序必须以当前 Vivado 版本的 routed 报告为准；资源相除得到的神经元数量只能作为估算。
- 旧 D2 图像识别结果没有通过能力门，不能把它写成剪枝有效性证据。

所有报告必须区分：软件精度、RTL 周期、OOC 物理结果、系统级吞吐、板上实测功耗。不能用其中一项替代另一项。

## 3. 职责边界

### 3.1 传统 NPU：数据平面

- 保存和读取 INT8 权重与激活。
- 完成乘加、累加、偏置和激活函数。
- 按 `issue_mask` 决定是否发出某条权重读取和对应 lane 操作。
- 输出每层必要的活动统计和可审计的工作量计数。
- 不生成标签、奖励或剪枝结论。

### 3.2 神经元控制器：控制平面

- 观察输入活动、输出发放、局部贡献和延迟调制。
- 维护每组连接的低位宽 utility/evidence。
- 在安全边界产生严格 `2:4` 的 `structural_mask`。
- 把结构掩码与当前输入活动相交，生成 `issue_mask`。
- 使用 `shadow -> verify -> commit/rollback` 机制发布结构变化。
- 不在 MAC 正在执行时改写活动掩码，不直接改写 NPU 权重，不在片上计算全局损失。

### 3.3 PS/Host：实验与调度平面

- 提供样本、标签、奖励、训练调度和日志存储。
- 选择何时开始观察、提交或清除，但不能在 TRAIN 中直接指定最终掩码。
- 负责跨时钟域、DMA、网络输入和结果回收。
- 不把 Host 写入的掩码伪装成本地自动剪枝证据。

## 4. V1 NPU 基线

第一版选择固定、容易审计的 INT8 MLP，不先追求通用卷积引擎：

```text
64 输入特征 -> 32 隐藏单元 -> 10 输出类别
```

选择理由：

- 比已有 `4 -> 2 -> 2` 足够大，能暴露层间带宽、存储和门控问题。
- 比原始 `784 -> 128 -> 10` 更容易在 XC7Z020 上完成完整回归。
- 每组四条连接，天然适配已签核的 `2:4` 控制器。
- 10 个 one-hot 输出便于记录正确率、覆盖率和 abstain，不引入二进制类别编码的非法组合。

V1 固定参数：

| 项目 | 冻结值 |
|---|---|
| 权重/激活 | signed INT8 |
| 累加器 | 至少 signed INT24；具体位宽由溢出向量冻结 |
| 分组 | 连续四条连接一组 |
| 稠密模式 | 四条连接全部可发射 |
| 稀疏模式 | 每组恰好保留两条连接 |
| 激活门控 | `issue_mask = structural_mask & activity_mask` |
| 第一版激活 | ReLU 或等价非负饱和函数，二选一后写入黄金模型 |
| 输出 | 10 路 one-hot，允许 `abstain` |
| 训练 | 片外调度，片上只执行既有局部事件更新 |

V1 不实现浮点、反向传播、片上损失函数、全局排序、任意稀疏率或随机每 tick 改结构。

## 5. 剪枝与门控协议

### 5.1 两类掩码

- `structural_mask`：在 TRAIN 的安全边界产生，四位中必须恰好两位为 1。
- `activity_mask`：当前 tick 根据四个输入是否需要计算产生。
- `issue_mask`：两者按位与，必须在 BRAM 读请求和 MAC/lane 发射之前形成。

必须分别记录：

- 因结构掩码跳过的读取和操作；
- 因输入本来为零而跳过的读取和操作；
- 因不应期、空闲或输出未使能而跳过的工作。

三者不能重复计数。

### 5.2 安全更新边界

一次样本或一个观察窗口执行：

```text
dense warm-up
  -> OBSERVE
  -> shadow mask
  -> verify exact-two
  -> PRUNE_COMMIT
  -> sparse fine-tune
  -> INFER freeze
```

提交期间旧掩码继续服务当前计算；新掩码只有在当前事务结束、校验成功并完成 commit 后，才能成为下一 tick 的有效掩码。校验失败必须 rollback，不得出现短暂 `1:4`、`3:4` 或未知位。

V1 中 `mask_valid=1` 后不自动恢复被剪连接。恢复只能通过 CONFIG 的 `PRUNE_CLEAR` 或后续单独批准的 NP8 动态恢复方案。

### 5.3 神经元输入

每个四连接组接收归一化后的本地证据：

- ENeuron：读取已提交的 evidence snapshot；
- Pulse-Mini-L：读取 FEEDBACK 接受沿锁存的 evidence；
- Pulse-Mini-L2：沿用独立的多级 evidence 适配器。

NP2 已选定三模型 gain=`1/2/1`。在 NPU 集成中仍需保持三条模型路径独立，不能借用某一模型的证据替代另一模型。

## 6. N0-N7 任务分解

### N0：冻结接口与黄金参数

当前形成的 N0 候选冻结值（提交审核，不等同于管理员批准）：

| 项目 | 候选值 |
|---|---|
| 拓扑 | `64 -> 32 -> 10` |
| 数据格式 | signed INT8 权重与激活 |
| 累加 | signed INT24，逐次饱和 |
| 隐藏激活 | ReLU 后饱和到 INT8 |
| 输出解码 | 10 路 one-hot；类别并列按较小编号；可选 margin abstain |
| 分组 | 每个输出的连续四条连接为一组 |
| dense 存储 | 每组 4 个 INT8 权重，占 2 个 20-bit 逻辑字 |
| lane 周期 | 每 lane 每拍处理一个四连接组；按组编号、输出编号顺序执行 |
| 结构门控 | `issue_mask = structural_mask & activity_mask`，但 N1 dense 暂固定为全开 |
| 层间语义 | N1 先完成隐藏层，再用隐藏结果计算输出层；启动/排空/背压另行计账 |

- [ ] 管理员审核并冻结 `64 -> 32 -> 10`、INT8、累加器宽度、激活函数、tick 与层间延迟。
- [ ] 冻结权重布局、四连接分组、mask 编码、命令响应和错误码。
- [ ] 冻结 dense/sparse 的计数口径，以及样本边界和 flush 语义。
- [ ] 输出接口合同、状态转移表和黄金向量。

门槛：Python 参考模型可以独立解释每个输入、读取、发射和状态变化。

### N1：dense INT8 NPU 基线

- [x] 实现不带剪枝的共享 lane NPU Python 参考模型（`npu_dense_reference.py`）。
- [x] 在软件合同中固定 1/2/4/8 lane 的周期、吞吐和逻辑 BRAM 读取口径；物理 BRAM 映射仍待 RTL/Vivado。
- [x] 完成随机权重、边界值、累加溢出、激活和 lane 不变量测试。
- [x] 建立 dense 的软件读取、发射和周期基线；固定十类 codebook smoke task 可在无神经元条件下正确解码。

门槛：dense Python/RTL 逐 tick 一致；不依赖神经元也能完成任务。当前已完成 Python 侧，RTL 侧待实现。

### N2：软件神经元门控闭环

- [ ] 将三种神经元接到同一 NPU Python 模型。
- [ ] 比较 dense、随机 `2:4`、权重幅度、局部 utility 和 activity-only 门控。
- [ ] 保留立即剪枝损失、微调恢复量和最终精度，禁止只展示恢复后最好结果。
- [ ] 记录每层 reads、ops、cycles、coverage、abstain 和 mask 稳定性。

门槛：至少 10 个固定 seed；稀疏模型相对 dense 的 BAcc 和 coverage 下降均不超过 2 个百分点；结构工作量减少达到 45% 才能进入 RTL。

### N3：NPU 读取前门控 RTL

- [ ] 将 `issue_mask` 接入 BRAM 地址/读使能和 lane 发射器。
- [ ] 增加 dense/sparse 对照计数器，确认门控发生在读取前而非 MAC 之后。
- [ ] 为 `issue_mask=0` 建立零突触快速路径，同时保持神经元时间状态一致。
- [ ] 增加非法 mask、忙时命令、重复 commit 和 INFER 冻结测试。

门槛：随机事务下 Python、RTL 的 mask、读取、发射和输出逐项一致。

### N4：shadow/commit/rollback

- [ ] 维护 active mask 与 shadow mask 两份状态。
- [ ] commit 前执行 exact-two、版本号、边界和来源检查。
- [ ] 失败时回滚到 active mask，成功时单拍切换 epoch。
- [ ] 验证神经元不会在 NPU 忙时直接改写 active mask。

门槛：原子性和 exactly-once 通过定向形式检查；任何非法命令无架构副作用。

### N5：三模型协同仿真

- [ ] ENeuron、Pulse-Mini-L、Pulse-Mini-L2 分别运行相同 NPU 任务。
- [ ] 覆盖 dense warm-up、observe、commit、fine-tune、infer、flush。
- [ ] 加入标签打乱、证据反号、随机 mask、过早提交和门控后置的负对照。
- [ ] 生成可审计账本：commit ID、utility、旧/新 mask、reads、ops、cycles 和冻结指纹。

门槛：三模型都完成正向与负向闭环；负对照不能同时通过主实验门槛。

### N6：XC7Z020 物理成本

- [ ] 使用目标 Vivado 版本对 dense NPU、剪枝控制器、神经元控制器和组合系统分别综合实现。
- [ ] 报告 LUT、FF、BRAM、DSP、WNS、WHS、TNS、THS、DRC 和路由状态。
- [ ] 分别给出单 lane、四 lane、八 lane 和完整 `64 -> 32 -> 10` 增量。
- [ ] 用相同活动序列生成 SAIF/VCD，比较动态功耗；vector-less 结果只能作估算。

门槛：100 MHz routed 的 setup/hold 零失败；资源和功耗结论必须有对应报告文件。

### N7：系统与网口闭环

- [ ] 接入 Host Bridge、FIFO、DMA 或网口数据流。
- [ ] 测量 dense、静态 `2:4`、结构+活动门控三种模式的持续吞吐。
- [ ] 测试 FIFO 不溢出、CDC、丢包、背压和结果顺序。
- [ ] 在同一输入、权重和时钟条件下比较端到端延迟、吞吐、功耗和温升。

门槛：只有板上实测通过后，才可报告“系统级性能提升”；否则只报告 RTL 周期或仿真结果。

## 7. 统一验收指标

### 任务能力

- dense 基线先达到预注册任务门；dense 失败时不得做剪枝正向结论。
- 稀疏模型 BAcc、coverage 相对 dense 下降不超过 2 个百分点。
- 至少 8/10 seed 不低于同稀疏率随机对照。
- 记录立即剪枝损失、微调样本数和恢复后的结果。

### 真实工作量

- 结构密度固定为 50%。
- 稠密激活条件下，实际权重读取和突触/MAC 发射至少减少 45%。
- 共享 lane 每组周期至少减少 35%；否则只能称存储或活动门控收益。
- 不把输入本来为零、不应期和失败样本造成的空操作算成剪枝收益。

### RTL 与物理实现

- 同一输入和事务序列 bit-exact、确定性复现。
- 至少 20 个 seed × 1000 个混合事务。
- exact-two、非法命令无副作用、INFER 冻结、重复提交和原子切换均有形式覆盖。
- XC7Z020、100 MHz routed：WNS/WHS ≥ 0、TNS/THS=0、setup/hold 零失败、DRC Error=0。

## 8. 资源规划口径

下面只定义测量方式，不把估算写成实测：

1. 先报告 dense NPU 的基线资源，再报告加入神经元控制器和门控后的增量。
2. BRAM 必须同时报告容量、端口、读延迟和实际读请求，不只报告位数。
3. DSP 使用量必须区分乘加数据平面与神经元控制平面；神经元不应因为局部评分引入大规模 DSP。
4. LUT/FF 资源相除得到的理论核数，不得替代阵列 routed 证据。
5. 任何性能提升都要同时给出基准时钟、lane 数、输入事件率、批大小和 Host/网口开销。

## 9. 当前停止条件

- N0 未获批准前，不修改 NPU 业务 RTL。
- dense 基线未通过前，不开始正式剪枝性能结论。
- 读取前门控未被计数器和负对照证明前，不称“跳算”。
- 100 MHz routed 未通过前，不报告可部署的神经元/NPU 数量。
- 板级链路未通过前，不报告网口端到端加速。
- 任一阶段失败时，保留失败证据并降级声明，不通过删除功能制造资源或时序结果。

## 10. 推荐顺序

```text
用户审核 N0
  -> dense NPU 基线 N1
  -> 软件神经元闭环 N2
  -> 读取前门控 N3
  -> shadow/commit/rollback N4
  -> 三模型协同仿真 N5
  -> XC7Z020 物理成本 N6
  -> 网口/板级系统 N7
```

当前结论：项目已经具备局部结构化剪枝控制器和神经元证据适配器，但“传统 NPU 与神经元在 FPGA 上协同并获得端到端收益”仍是待证明目标。
